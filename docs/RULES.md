# 规则与版本路线图

本文汇总 `cn-linebreak` 的规则实现状态与演进路线，整理自
《cn-linebreak 更新建议与规则路线图》。

## 核心表达

> 中文断行不应由浏览器按单字随机决定；应先划分语义单元，再明确"可断、必断、不可断"三类边界。

| 表达方式 | 含义 | 实现 |
|---|---|---|
| `<wbr>` | 此处可以换行 | `insertWbr()` 自动插入 |
| `<br>` | 此处必须换行 | 孤字行/行首行尾禁则检查 |
| `.no-break` | 此内容不可拆分 | 深度感知跳过 + 过长告警 |
| `word-break: keep-all` | 默认禁止任意拆字 | CSS 覆盖分析 |

## 规则类型

| 类型 | 含义 | 当前实现 |
|---|---|---|
| `mandatory` | 必须换行 | `<br>` 已存在（供渲染模式使用） |
| `allowed` | 可以换行 | 标点后 `<wbr>` 插入点 |
| `prohibited` | 绝对禁止 | 行首闭式标点、行尾开式标点、保护词内不插 `<wbr>` |
| `preferred` | 优先选择 | v0.3.0 候选评分 |
| `discouraged` | 尽量避免 | v0.3.0 句法软规则 |

## 已实现规则（v0.1.1）

- 排版硬规则：行首禁闭式标点、行尾禁开式标点（CLReq / GB-T 15834）；
- 孤字行（显式 `<br>` 行仅 1 字 + 句号 → 错误，≤ `minLastLineCjk` 字 → 警告）；
- 长文案零换行点（≥ `minCjkLength` 汉字且无 `<wbr>`/`<br>`）；
- `.no-break` 过长（>14 汉字）；
- 保护词典：`<wbr>` 不落在词内；词被 `<br>` 拆开报错；
- CSS：`keep-all` 覆盖 `trusted/partial/none`、全局 `nowrap` 误用、缺 `line-break: strict`。

## 版本路线图

- **v0.1.1（已完成）**：公开使用体验——README 能力边界、CLI 退出码/`--help`/`--version`/
  `--strict`/`--config`、修复后复审、void elements、`.no-break` 深度嵌套、行内标签末尾标点、
  CSS 覆盖分析、CI、DSH 标准插件包。
- **v0.2.0：规则配置化**——Unicode Line_Break 数据（官方 `LineBreakTest.txt`）、
  更完整的 CLReq 禁则与标点配对、保护词典与配置文件成熟化、`Intl.Segmenter` 词边界（可选）。
- **v0.3.0：候选评分**——词性类别、句法软规则、候选打分（标点边界奖励 / 句法成分奖励 /
  保护词惩罚 / 末行孤字惩罚）、整段全局最优断行；可选 Stanza/LTP 后端；默认保持零依赖。
- **v0.4.0：真实渲染审查**——`--render --viewport`，读取浏览器真实行框，检查自动换行产生的
  孤字行、保护词跨行、标点实际行首行尾，输出元素选择器与实际行内容。

## 推荐的四层结构

1. Unicode 字符级断行规则（UAX #14）；
2. CLReq 与国家标准的中文排版规则（CLReq / GB-T 15834）；
3. 分词、词性与句法软规则（GB-T 13715 / GB-T 20532 / Intl.Segmenter / UD 中文树库）；
4. 项目保护词典与真实渲染验证。

> 先确定合法换行点，再依据中文语义和版面质量给候选打分；硬规则负责避免错误，软规则负责让结果更像人写的。
