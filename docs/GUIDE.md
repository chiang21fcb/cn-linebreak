# 中文网页文案断行修复指南

> 本文档是 cn-linebreak 工具的规则来源与验收标准。工具实现的每一条检查都对应本文档中的某条规则。

## 适用场景

适用于中文演示页、落地页、海报式网页、数据大屏等对断句节奏要求较高的界面。

典型问题包括：

- 一行末尾或下一行只剩"一个字 + 句号"。
- 完整词组被从中间切开，例如"产品培训专员"被排成"产｜品培训专员"。
- 动宾结构被拆散，例如"落盘成｜公司资产"。
- 引号、强调文字或产品名在换行时被拆开。
- 标题虽然没有溢出，但上下两行不符合中文停顿习惯。

## 核心结论

不能只依赖浏览器自动判断中文词组。

`text-wrap: pretty`、`text-wrap: balance` 和 `word-break: auto-phrase` 可以辅助排版，但不同浏览器、版本和字号下的结果并不稳定。对于演示稿和强设计页面，应由文案作者明确指定：

1. 哪些位置允许换行；
2. 哪些语义单元绝对不能拆开；
3. 哪些位置必须强制换行。

## 推荐实现

### 1. 默认禁止中文任意拆字

```css
:where(h1, h2, p, .card-body, .step-body, .micro, th, td) {
  line-break: strict;
  word-break: keep-all;
  overflow-wrap: normal;
}
```

作用：避免浏览器把连续中文当成任意可断开的单字序列。

注意：使用 `keep-all` 后，必须为较长文案主动提供合理的换行点，否则窄屏可能溢出。

### 2. 使用 `<wbr>` 标记"可以换行"的语义边界

`<wbr>` 只提供换行机会；空间足够时不会产生换行，也不会显示额外字符。

```html
<h2>WB 二期作业：<wbr>选一个致趣模块，<wbr>做培训材料。</h2>

<p>
  AI 现场写插件<wbr>
  → 读产品手册<wbr>
  → 按培训结构输出<wbr>
  → 换模块一句话再跑。
</p>
```

优先在以下位置添加 `<wbr>`：

- 逗号、分号、句号之后；
- 冒号后的解释内容之前；
- 破折号两侧的完整语义段之间；
- 流程箭头前后；
- 并列结构之间；
- 主句与补充说明之间；
- 标题中自然停顿的位置。

不要在以下位置添加 `<wbr>`：

- 固定产品名内部；
- 人名、岗位名、专有名词内部；
- 数字与单位之间；
- 动词与不可分割的宾语之间；
- 引号内部的完整名称中间；
- 一个短语只剩最后一两个字的位置。

### 3. 使用不可拆容器保护完整表达

对于产品名、岗位名、引号内容或必须完整呈现的短语，使用不可拆容器：

```css
.no-break {
  white-space: nowrap;
}
```

```html
<h2>
  <span class="no-break">落盘成<b>“产品培训专员”</b></span><br>
  预设。
</h2>
```

这能避免出现：

```text
落盘成"产
品培训专员"
```

需要注意：不可拆短语不能太长。若在目标屏幕宽度内放不下，应调整字号、容器宽度，或在更上层的语义边界换行，不能继续在词组内部切断。

### 4. 使用 `<br>` 表示"必须换行"

`<br>` 适用于已经确定的演示节奏，例如标题的上下两拍：

```html
<h2>一整条工作链，<br>每个环节都是工具。</h2>
```

区分三种手段：

| 手段 | 含义 | 适用范围 |
|---|---|---|
| `word-break: keep-all` | 默认不拆中文词组 | 全局基础规则 |
| `<wbr>` | 此处可以换行 | 自适应文案 |
| `<br>` | 此处必须换行 | 固定演示节奏 |
| `.no-break` | 此内容绝对不能拆 | 产品名、引号内容、完整短语 |

## 中文断句原则

### 标题

标题应按"语义拍子"换行，而不是追求机械的字数相等。

推荐：

```text
三种扩展，
三种自由。
```

不推荐：

```text
三种扩展，三
种自由。
```

### 正文

正文优先按以下层级寻找换行点：

1. 句号、问号、感叹号之后；
2. 分号、破折号之后；
3. 逗号之后；
4. 并列项之间；
5. 主谓、动宾等完整语义块之间。

不要为了让两行字数接近而破坏句法结构。

### 流程文案

流程箭头天然是换行边界，但箭头不应孤零零地出现在行首或行尾。建议把换行机会放在每个完整步骤之间：

```html
读产品手册<wbr> → 提取事实<wbr> → 输出文档
```

### 中英文混排

- 英文产品名、文件名和命令应作为整体保留。
- 中文与英文之间的空格需统一。
- 引号建议统一使用中文弯引号 `“”`。
- `AI`、`Git`、`web UI` 等短词不要从中间拆开。

## 实际执行流程

### 第一步：列出所有承载文案的元素

至少覆盖：

- `h1`、`h2`；
- 正文 `p`；
- 卡片正文；
- 步骤说明；
- 表格单元格；
- 小字注释；
- 强调文字和引号内容。

不要只修用户指出的一个标题。一个位置出现问题，通常说明整页都在依赖不稳定的自动断行。

### 第二步：逐条标注语义边界

对每条文案依次判断：

1. 这句话有哪些完整词组？
2. 哪些词组不能拆？
3. 最自然的停顿在哪里？
4. 空间不足时，优先在哪些位置换行？
5. 是否存在只剩一两个字的风险？

### 第三步：添加断行控制

- 全局使用 `keep-all`；
- 在自然停顿位置添加 `<wbr>`；
- 对完整名称使用 `.no-break`；
- 对固定演示节奏使用 `<br>`。

### 第四步：全量复查

逐页检查，而不是仅搜索某个词：

- 标题是否按完整语义分行；
- 引号内文字是否完整；
- 强调色文字是否被错误拆开；
- 句末是否出现孤字；
- 标点是否单独占行；
- 英文、文件名、命令是否被拆开；
- 卡片和表格在较窄区域是否溢出。

### 第五步：结构校验

修改完成后至少确认：

- 页面数量未变化；
- 标签成对闭合；
- 原有脚本、动画和交互没有被改动；
- `<wbr>` 只出现在合理的语义边界；
- `.no-break` 内没有不必要的超长内容；
- 文件编码仍为 UTF-8。

## 验收清单

逐页回答以下问题，全部为"是"才算完成：

- [ ] 每一行都是可以独立朗读的语义片段。
- [ ] 没有完整词组被从中间拆开。
- [ ] 没有“一个字 + 标点”单独留在末行。
- [ ] 产品名、岗位名和引号内容保持完整。
- [ ] 动宾结构没有被不自然地拆散。
- [ ] 箭头、加号等连接符没有孤立成行。
- [ ] 标题换行符合讲述节奏。
- [ ] 正文换行符合中文停顿习惯。
- [ ] 窄容器内没有横向溢出。
- [ ] 页面结构和交互功能保持不变。

## 常见错误

### 只添加 `text-wrap: pretty`

问题：不同浏览器对中文的处理结果不一致，不能保证完整词组不被拆开。

### 只使用 `word-break: auto-phrase`

问题：兼容性和词组识别结果不稳定，专有名词尤其容易识别失败。

### 全局使用 `white-space: nowrap`

问题：所有文字都无法换行，窄屏会直接溢出。

### 只修肉眼看到的一个位置

问题：同一套自动断行规则仍会在其他页面产生类似问题。

### 为了视觉均衡随意插入 `<br>`

问题：固定换行可能只适合当前屏幕尺寸；应优先使用 `<wbr>`，只在确实需要固定节奏时使用 `<br>`。

## 可复用原则

一句话总结：

> 中文断行不应由浏览器按单字随机决定；应先划分语义单元，再明确“可断、必断、不可断”三类边界。
